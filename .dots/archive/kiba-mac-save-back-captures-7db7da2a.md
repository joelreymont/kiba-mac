Problem (oracle core 2026-09-25: prior #5 still open, new High 3, Medium 1, Medium 2): (a) Switcher.save/put read isMixed and files.login() before store.write, so another process's install (its second transaction writes config then credentials inside store.write) can be seen half done and the B/A pair saved; capture inside the transaction and the SQLite write lock excludes it. (b) A failed ClaudeLive.install can leave credentials C live with config A restored and pending C retained; Switcher.liveNames protects only A, so probeAll refreshes saved C's token though it is live; another failed repair can replace pending C by another name, so protecting the pending name is not enough. (c) ClaudeLive.isMixed returns true on a pending marker before reading the live files, so use() skips the orphanLive check DESIGN promises (credentials without a config) and installs over orphan credentials. (d) Switcher.probeAll appends a Probed with the original outcome even when record() threw, so a .revoked outcome whose delete rolled back is reported as removed. Acceptance: (1) put runs files.login(), liveName and tx.put inside one store.write; save runs isMixed inside that same write; DESIGN save/importLogin bullets say so. (2) While store.pending(.claude) is set, probeAll(.claude) probes nothing: it returns saveBackError = KibaError.mixed.reason and providerError naming the pending repair (one KibaError case with a reason, no string literal), accounts empty; redeem(.claude, n) throws the same error; DESIGN Probing says a pending Claude repair stops all Claude probes and refreshes until use() completes it. (3) isMixed reads login() first (orphanLive propagates) and only then consults pending; DESIGN 'Reading the live login' matches. (4) probeAll skips the Probed append when record() throws (the provider error still names the account); DESIGN ProbeReport says accounts holds only recorded outcomes. Tests (integration, through Switcher/StatusReader/AppModel as the existing ones do): pending set + saved rows → probeAll makes no HTTP request and reports the error, AppModel shows it; pending set + orphan creds → use throws orphanLive and pending stays; a record failure (e.g. row forgotten during the probe, as existing tests do) → report accounts exclude it and AppModel's tally does not count it removed.
