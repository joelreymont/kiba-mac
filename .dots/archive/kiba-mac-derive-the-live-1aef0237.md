Problem (oracle core 2026-09-25: new High 1, Medium 3, Medium 4): (a) Paths.loginService applies Claude Code's derivation (service = base + '-' + first 8 hex of SHA-256 of the NFC config dir path when CLAUDE_CONFIG_DIR is non-empty) only to the throwaway login; the live paths.keychainService stays the bare 'Claude Code-credentials' even when the app's environment sets CLAUDE_CONFIG_DIR, so ClaudeLive pairs config B's identity with item A's credentials. (b) PrivateFS.isFile returns false for an existing directory, FIFO or socket at .credentials.json, so LiveSecret.chosen silently selects the Keychain; DESIGN says only ENOENT/ENOTDIR selects it. (c) JSONFields.Tree keys its dictionary by Swift String, whose equality is canonical equivalence, so a document with keys 'é' and 'e\u0301' (valid, distinct for JSONDoc) fails as a duplicate-key document; escaped lone surrogates in keys also collapse. Acceptance: (1) one derivation Paths.service(for dir: URL?) (name yours): base + suffix; keychainService = service for the CLAUDE_CONFIG_DIR the app was given (nil → bare), loginService = service for claudeConfigDir(root: loginRoot(.claude)); the test seam stays (tests pass their base service; loginService and a CLAUDE_CONFIG_DIR-derived live service stay under kiba-mac-test-); DESIGN Paths block and ClaudeSecrets say so. (2) LiveSecret.chosen: a regular file → file; ENOENT/ENOTDIR → Keychain; anything else that exists → KibaError.io naming the path and its kind; DESIGN ClaudeSecrets matches. (3) JSONFields keys by the decoded key bytes (Data), matching JSONDoc.Locator; str/obj/objs take the key as the app's String and look it up by its UTF-8 bytes. Tests (integration): a scratch env with CLAUDE_CONFIG_DIR set → StatusReader/Switcher use the derived live service (FakeKeychain or a kiba-mac-test- KeychainItem under the derived name) and the bare one is never read; a directory at .credentials.json → save/status report the io reason, nothing written to the Keychain; a config whose oauthAccount holds both 'é' and 'e\u0301' keys beside emailAddress → identity reads fine.
